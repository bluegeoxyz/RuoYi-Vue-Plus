# TASK-V1-005 工程模块依赖审计

## 1. Maven reactor

根 `pom.xml` 的直接 reactor 为：`ruoyi-admin`、`ruoyi-common`、`ruoyi-extend`、`ruoyi-modules`、`ruoyi-api`。仓库实际共 43 个 Maven 模块。

`ruoyi-modules/pom.xml` 聚合：

`ruoyi-demo`、`ruoyi-gen`、`ruoyi-job`、`ruoyi-system`、`ruoyi-hr`、`ruoyi-property`、`ruoyi-warehouse`、`ruoyi-workflow`、`ruoyi-ai`。

因此用户描述中的 `ruoyi-module` 应理解为实际目录 `ruoyi-modules`；它不是一个可独立删除的示例模块。

## 3. 间接依赖

### 3.1 删除 demo 后仍需保留的公共能力

- `ruoyi-common-push`、`ruoyi-common-sms` 仍被 `ruoyi-system` 和/或 `ruoyi-workflow` 使用。
- `ruoyi-common-mail` 仍被 `ruoyi-admin` 和 `ruoyi-workflow` 使用。
- `ruoyi-common-mcp` 被 `ruoyi-admin` 直接依赖，不能随 demo 自动删除。
- 客户敏感字段链仍依赖 security/sensitive/encrypt 类公共能力，禁止因 demo 示例引用而一并删除。

### 3.2 删除 demo 后可继续审计的叶子模块

`ruoyi-common-elasticsearch`、`ruoyi-common-mqtt` 的业务模块 POM 引用仅落在 `ruoyi-demo`（另有 BOM/自身声明）。若无外部自动配置需要，可作为第二层候选；必须先验证 admin 的 classpath、配置和启动。

### 3.3 AI 链

- 后端：`ruoyi-ai` -> `ruoyi-common-ai` -> Snail AI starters。
- 服务端：`ruoyi-extend/ruoyi-snailai-server`。
- 前端：`src/views/ai/chat/index.vue`、`src/api/ai/agent/**`、monitor AI 页面。
- 部署：`script/docker/docker-compose.yml`、Nginx `snailai-server` upstream/location、`ruoyi-admin/Dockerfile`。
- SQL：核心初始化 SQL 含 AI 菜单。

只移除 `ruoyi-ai` 会留下失效页面、菜单和部署配置。

### 3.4 Job 链

- `ruoyi-job` 依赖 `ruoyi-common-job`；后者封装 SnailJob client starters。
- `ruoyi-extend/ruoyi-snailjob-server` 是独立服务。
- Docker Compose、Nginx、前端 monitor 页面、核心菜单、`script/sql/ry_job.sql` 都有引用。
- 当前 `ruoyi-job` 的类名/实现包括多种 `Test*` executor 及支付宝/微信账单示例，未发现物业、收费、仓储模块对其 import。

### 3.5 Workflow 链

- `ruoyi-workflow` 依赖 WarmFlow、`ruoyi-common-liteflow`、push/mail/sms 等。
- `ruoyi-api` 保留 `org.dromara.workflow.api` 接口/DTO/event；即便删除实现模块，也必须处理 API 契约。
- 前端通用 `Process` 组件直接 import workflow API。
- 当前开发库没有 `flow_*` 或 `test_leave` 表，说明“代码存在/配置启用”与“数据库可运行”未闭环。

## 4. 建议的阶段 B 删除批次（须人工确认）

### 批次 B1：demo

同步范围：`ruoyi-demo` 目录、根 dependencyManagement、`ruoyi-modules` module、`ruoyi-admin` dependency、前端 demo views/API、核心 SQL 中 demo 菜单与 `test_*` 定义、仅 demo 使用的公共叶子依赖。开发库物理表不在阶段 B 删除。

### 批次 B2：job（若确认）

同步范围：job client module/common wrapper、SnailJob server、前端控制台、菜单、配置、Docker/Nginx、独立 SQL 与文档。先确认未来是否需要物业定时账单、对账或调度；当前代码里的账单类只是示例，不能作为已实现业务能力。

### 批次 B3：AI（若确认）

同步范围必须覆盖 3.3 的完整链。AI 默认关闭只证明当前配置不启用，不证明可删除。

### 批次 B4：workflow/gen（单独产品决策）

工作流优先决定“完整启用并纳入 V1 数据库”或“完整移除”；代码生成器优先考虑 Profile/打包隔离。二者不与 demo 批量删除。

## 5. 每批验收门禁

1. Maven reactor/effective dependency 不再引用已删除 artifact。
2. 后端全量编译、测试、Spring Boot 启动。
3. 前端 typecheck、lint、Vitest、build。
4. 菜单 component 与前端页面双向检查；权限码四方检查。
5. Docker/Nginx/部署脚本不再引用删除服务。
6. 新增跳过测试数为 0；现有环境阻塞项不得通过放宽安全条件掩盖。

阶段 A 未执行以上删除或门禁。

# TASK-V1-008-A Spring Boot dev/prod 配置规范化验收报告

## 1. 结论

本次完成配置与 Docker 环境变量适配，未修改 Java/Vue 业务代码、数据库数据或 `V1__initial_schema.sql`。生产配置已消除数据库、Redis 与 JWT 的危险默认值；缺失必要变量时 JAR 会明确启动失败。33 模块生产打包与 Compose 配置解析通过。

由于仓库及 `script/docker/` 下不存在真实 `.env`，且未获得目标服务器凭据，本机未执行带真实身份的数据库登录、Redis AUTH、Flyway validate 和最终 HTTP 健康检查；这些项目保持阻塞，不能宣称服务器部署成功。

- `ruoyi-admin/src/main/resources/application.yml`：监听端口支持 `SERVER_PORT`。

- `script/docker/docker-compose.yml`：补齐 JWT、multipart、外部 URL 映射并挂载独立临时卷。
- `script/docker/.env.example`：补齐非敏感变量示例。
- `docs/deployment/docker-deployment.md`：增加变量映射与 fail-fast/Flyway 说明。
- `docs/README.md`：增加本报告索引。

## 5. 部署生效步骤

1. 将 `script/docker/.env.example` 复制为服务器 `/opt/zbm/.env`，填写容器 DNS、目标库、Redis 与安全密钥；权限设为 `600`。
2. 先执行 `docker compose --env-file .env config`，核对渲染后的数据库名与网络，不输出或提交该文件。
3. 新空库或已纳管库才设置 `ZBM_FLYWAY_ENABLED=true`；非空未纳管库必须保持关闭并先完成结构核对。
4. 发布 JAR 后启动 backend，观察 Flyway validate/migrate 与 Redis 连接日志。
5. 执行 `curl -f http://127.0.0.1:8080/actuator/health`，再启动前端代理。

## 7. Docker 部署结构最终定向优化

在不改变既有架构的前提下完成以下调整：

- Frontend 改为挂载稳定父目录 `/opt/zbm/frontend` 到 `/usr/share/nginx/zbm`，Nginx root 为 `/usr/share/nginx/zbm/current`。
- Backend 发布/回滚仍使用 `docker compose up -d --no-deps --force-recreate backend`，确保重新解析单文件 JAR bind mount。
- Frontend 发布/回滚只执行无强制重建的 `docker compose up -d --no-deps frontend` 和 `nginx -t`；运行中容器直接读取新 `current`。
- Backend 端口只发布到宿主机 `127.0.0.1`；Nginx 继续通过 Docker DNS `backend:8080` 访问。
- Runtime Dockerfile 移至部署目录 `script/docker/backend/Dockerfile`，构建上下文为 `script/docker/`，服务器 `/opt/zbm` 不再依赖 Maven 源码树。
- Backend release 将版本目录设置为可遍历、JAR 设置为全局只读；容器内 UID 100 的 `zbm` 用户可读取 JAR，并可写命名卷 `/app/logs`、`/app/temp`。

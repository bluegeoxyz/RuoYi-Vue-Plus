## 1. 审计口径

本清单来自实际代码、SQL、测试与构建结果，不以菜单名或历史任务记录单独作为“已实现”依据。状态含义：

- **已实现**：前后端、模型/SQL、权限主链路均有代码证据，且至少编译与相关自动化测试通过；不等同于人工验收通过。
- **部分实现**：主链路存在，但缺少关键端到端、数据库执行状态或部分子能力。
- **仅存在代码但不可确认可用**：代码/页面/SQL存在，但当前无法确认部署数据库、菜单绑定或运行验收。
- **未实现**：未找到足以构成功能的真实代码链路。
- **疑似废弃**：仍有代码或配置，但缺少调用/入口证据；未经验证不得删除。

## 2. 真实仓库结构

## 4. 未找到的独立能力

- 未找到独立“企业主数据”业务模块；当前组织来自系统部门，仓储公司范围亦复用部门。若 V1 产品定义要求企业档案、统一社会信用代码、企业生命周期等，应判为**未实现**。
- 未找到独立“账单”聚合实体；当前以 `pm_receivable` 作为应收/账单载体。若产品要求账单头、账单明细、账单发布/撤回，应判为**未实现**。
- 未找到退款、预收款余额、押金、坏账、财务结账等收费扩展能力。
- 未找到采购、供应商、销售、批次/序列号、成本核算等仓储扩展能力。

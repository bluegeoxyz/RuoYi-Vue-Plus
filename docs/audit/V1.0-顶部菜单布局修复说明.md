# V1.0 顶部菜单布局修复说明

## 修复结论

顶部菜单不再按 `document.body` 宽度估算容量，而是由 `TopNav` 自身容器的实际宽度、每个菜单项的真实测量宽度、菜单间距以及已渲染“更多菜单”的实际宽度共同计算。溢出入口使用不可压缩布局，不再被项目选择器及右侧工具栏挤压到接近零宽。

## 实现

- `src/components/TopNav/index.vue`：增加菜单容器与隐藏测量区引用；使用 `ResizeObserver` 监听真实容器；菜单变化后重新测量；卸载时断开 observer 并取消动画帧。
- `src/components/TopNav/layout.ts`：纯函数计算可见项数量；只有全部菜单都可容纳时才省略“更多菜单”，否则先为溢出入口和间距保留空间。
- CSS 将一级菜单和 overflow submenu 设置为 `flex: 0 0 auto`，并允许弹层溢出显示；未通过提高 `z-index` 或隐藏项目选择器规避问题。

## 验证

- Vitest 覆盖全部可见、折叠预留、极窄容器、ResizeObserver 回调与释放。
- 真实浏览器 662px CSS 视口下，“更多菜单”实测宽度 113.6px；可点击展开，9 个顶级入口完整显示，点击目标没有落到账号区域。
- 1280/1440/1920 的计算边界由同一纯函数及真实测量尺寸覆盖；本轮内置浏览器不能创建上述三个固定视口，未将计算验证写成对应尺寸的浏览器截图通过。

## 行为边界

本修复只调整导航布局与折叠计算，不改变菜单来源、权限码、项目选择策略或后端授权。

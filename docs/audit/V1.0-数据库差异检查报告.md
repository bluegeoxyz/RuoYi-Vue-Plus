# V1.0 数据库差异检查报告

## 检查方式

[Test-ZbmDatabaseDrift.ps1](../../script/audit/Test-ZbmDatabaseDrift.ps1) 只查询 `information_schema.TABLES`，仅允许库名 `zbm_property_test` 或 `zbm-data`。表、字段、主键、唯一约束、CHECK、字典、菜单和角色关联的补充统计也均使用 SELECT 完成。

## 实际结果（2026-10-13）

| 数据库 | 实际表数 | baseline 业务表 | 缺失 | 额外 pm/wm/hr 表 |
|---|---:|---:|---:|---:|
| `zbm-data`（开发，只读） | 61 | 37 | 0 | 0 |
| `zbm_property_test`（隔离测试） | 46（含环境标识） | 37 | 16 | 0 |

测试库统计：745 个字段、46 个主键、21 个唯一约束、44 个 CHECK 约束、27 个字典类型、97 个业务菜单。结构差异来自测试库尚未初始化仓储模块，而不是脚本静态推断。

### 测试库缺失表

`wm_inbound_order`、`wm_inbound_order_item`、`wm_inventory`、`wm_inventory_transaction`、`wm_material`、`wm_material_category`、`wm_outbound_order`、`wm_outbound_order_item`、`wm_stocktake_order`、`wm_stocktake_order_item`、`wm_transfer_order`、`wm_transfer_order_item`、`wm_unit`、`wm_warehouse`、`wm_warehouse_location`、`wm_warehouse_zone`。

## 结论

- 开发库业务表集合与当前 baseline 一致；这不代表字段、数据或业务验收全部一致。
- 测试库不能作为仓储集成测试环境，除非按已审批的测试初始化流程补齐结构。本任务没有自动执行 baseline 或 migration。
- 角色统计不能以角色名模式替代真实业务角色键；权限角色关联以 V2.0.32/V2.0.34 SQL 和权限契约测试为证据，未对开发库角色数据做写入修正。

# V1.0 数据库结构审计

## 1. 审计范围与限制

审计了 `script/sql/zbm/baseline/`、`migration/`、`seed/` 和 Java Entity/Mapper。未执行任何 SQL、未执行 migration、未修改 MySQL/Redis 数据。

后端测试日志证明测试进程在 2026-10-13 能连接 `localhost:3306` MySQL 和 `localhost:6379` Redis；但 `wsl docker ps` 本轮未返回可用容器清单，因此容器名、镜像、库名与当前 schema version 未确认。

## 2. 业务表基线

`baseline/01_schema.sql` 当前包含 39 张 ZBM 业务表：

- HR：`hr_employee`。
- 项目/资源：`pm_project`、`pm_project_member`、`pm_building`、`pm_unit`、`pm_room`。
- 客户/授权/审计：`pm_customer`、`pm_room_customer_rel`、两类 management grant 及 audit、敏感访问审计。
- 收费：`pm_charge_item`、`pm_charge_rule`、`pm_charge_binding`、`pm_receivable_batch`、`pm_receivable`、`pm_payment`、`pm_payment_allocation`、`pm_payment_reversal`。
- 仓储：`wm_warehouse`、`wm_warehouse_zone`、`wm_warehouse_location`、`wm_material_category`、`wm_unit`、`wm_material`、`wm_inventory`、`wm_inventory_transaction`，以及入库、出库、调拨、盘点头/明细表。

## 3. migration 状态

仓库存在 V2.0.1 至 V2.0.36 的脚本（含 V2.0.33.1 前置检查）。但：

- 未发现 Flyway 依赖或 `flyway_schema_history` 可验证链路。
- `migration/README.md` 与既有安全审计均将其描述为人工执行记录。
- 多个 migration 与 baseline 同时定义相同表；baseline 适用于新装，migration 适用于已有环境，两者必须明确入口，不能混合执行。
- baseline 与大量 migration 当前均处于未提交/修改状态，目标数据库实际状态无法由 Git commit 唯一复现。

结论：数据库“脚本支持”较完整，但“已部署结构”只能标记为**未确认**。

## 4. 模型一致性抽查

| 范围 | 结果 | 证据 |
|---|---|---|
| 收费表 | Entity 与 SQL 表名/主键/项目字段主干一致 | `charge/**/domain` 与 V2.0.16～22 |
| 仓库主数据 | warehouse/zone/location/material/unit 与 V2.0.23～24 一致 | `ruoyi-warehouse` Entity 与 SQL |
| 库存 | balance 与 transaction 分表，数量使用 decimal | V2.0.25～26；inventory domain |
| 单据状态 | SQL CHECK 与 Service 的 DRAFT/CONFIRMED/COMPLETED/CANCELLED 基本一致 | V2.0.27、29～31；各 OrderServiceImpl |
| 逻辑删除 | 主数据/单据多含 `del_flag` | baseline 与 Entity `@TableLogic` |

## 5. 风险清单

| 等级 | 风险 | 建议 |
|---|---|---|
| P1 | 无可信 schema version/执行账本 | 选择 Flyway 或受控手工 ledger；禁止伪造历史 |
| P1 | baseline 与 migration 均在持续修改，环境重建与升级路径可能分叉 | 建立新装与升级两条可重复验证流水线 |
| P2 | migration 菜单/角色 SQL 与 Java 权限码强耦合 | 增加只读权限契约检查并在 CI 校验 |
| P2 | 仓储大量新表尚无本轮真实 schema 对比 | 在专用测试库运行 information_schema 差异报告，不自动迁移 |
| P2 | 业务表主要靠应用校验和唯一/CHECK 约束，跨表外键较少 | 明确软外键策略，补孤儿数据诊断 SQL |
| P3 | V2.0.33 与 V2.0.33.1 容易被人工按文件名字典序误执行 | 手工 ledger 明确语义版本排序与前置检查 |

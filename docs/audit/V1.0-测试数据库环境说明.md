# V1.0 专用测试数据库环境说明

## 环境结论

- 运行平台：Windows + WSL2 `archlinux` + Docker。
- MySQL：容器 `jdpm-mysql`，MySQL 8.0，宿主端口 3306。
- Redis：容器 `jdpm-redis`，Redis 7，宿主端口 6379；集成测试固定使用 DB 15，开发配置使用 DB 0。
- 专用数据库：`zbm_property_test`。测试不得连接 `zbm-data` 或其他库。
- 专用账号：`zbm_test`，仅对 `zbm_property_test` 拥有 SELECT、INSERT、UPDATE、DELETE、CREATE TEMPORARY TABLES。密码仅通过环境变量传入，不写入仓库。
- 环境标识：`zbm_test_environment` 表必须同时存在 `environment=integration-test` 与 `database=zbm_property_test`。

本次未执行开发/生产 migration，未清理任何数据库或 Redis 数据。测试库标识表及专用账号是本次唯一数据库环境变更。

## 必需环境变量

```powershell
$env:ZBM_TEST_MYSQL_URL='jdbc:mysql://127.0.0.1:3306/zbm_property_test?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true'
$env:ZBM_TEST_MYSQL_USERNAME='zbm_test'
$env:ZBM_TEST_MYSQL_PASSWORD='<local secret>'
$env:ZBM_TEST_REDIS_HOST='127.0.0.1'
$env:ZBM_TEST_REDIS_PORT='6379'
$env:ZBM_TEST_REDIS_PASSWORD='<local secret>'
$env:ZBM_TEST_REDIS_DATABASE='15'
$env:ZBM_TEST_AES_KEY='<32-byte test key>'
$env:ZBM_TEST_HMAC_KEY='<base64 test key>'
```

## 安全门禁

使用 [Invoke-ZbmIntegrationTests.ps1](../../script/audit/Invoke-ZbmIntegrationTests.ps1)：

- JDBC URL 必须明确包含 `/zbm_property_test`；
- 用户名不得为 `root`；
- Redis DB 必须为 15；
- 启动前读取并核验测试库环境标识；
- 不自动建库、不自动跑 migration、不清表；
- 环境变量缺失或标识不符立即失败。

示例：

```powershell
.\script\audit\Invoke-ZbmIntegrationTests.ps1 -Scope Single -TestClass ChargeItemMySqlTest
.\script\audit\Invoke-ZbmIntegrationTests.ps1 -Scope Property
.\script\audit\Invoke-ZbmIntegrationTests.ps1 -Scope Http
```

## 已知权限边界

测试账号未授予 `DROP`、`CREATE TRIGGER`、`SUPER` 或全局权限。这使 6 项会创建持久探针表/触发器的测试保持阻塞。该限制是有意的：当前不能证明这些 DDL 在共享容器中可安全隔离，不能通过扩大高危权限换取表面通过。

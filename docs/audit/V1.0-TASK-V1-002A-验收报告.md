## 3. 目标失败测试分析与修复

### 3.1 原因

测试以 `WebApplicationType.NONE` 启动完整 `DromaraApplication`。`SpringDocConfig` 构造器依赖 `ServerProperties`，但非 Web 上下文不提供该 Bean。原测试使用 `SpringApplicationBuilder.properties(...)` 设置属性；这是默认属性源，优先级低于项目配置，所以即使增加 `springdoc.api-docs.enabled=false`，SpringDoc 仍会被启用并提前中断上下文。

### 3.2 修复方式

测试通过 `.run(...)` 传入以下高优先级命令行参数：

- `--mybatis-encryptor.enable=false`
- `--property.customer.security.enabled=false`
- `--springdoc.api-docs.enabled=false`

断言未删除、未弱化、未禁用。最终异常链包含 `Customer security configuration incomplete: mybatis-encryptor 必须启用`，并继续断言错误信息不得泄漏硬编码 AES 密钥。

### 3.3 单独执行结果

```powershell
.\mvnw.cmd -pl ruoyi-admin -am "-Dtest=CustomerSecurityApplicationStartupTest" "-Dsurefire.failIfNoSpecifiedTests=false" test
```

结果：通过。`Tests run: 1, Failures: 0, Errors: 0, Skipped: 0`，reactor 38/38 成功。

执行过程中完整应用在安全校验失败前建立了到本机 MySQL、Redis 的连接，但该测试自身没有执行数据库写操作。后续可考虑把“完整应用启动”与“配置绑定/安全校验”拆为两个层级，但本任务未扩大生产代码改动范围。

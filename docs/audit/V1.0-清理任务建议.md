# V1.0 清理任务建议

本文件仅给出 TASK-V1-002 候选，不代表已获准修改。

## 1. 建议优先级

### 第一批：稳定性门禁（优先）

1. 修复 `CustomerSecurityApplicationStartupTest` 的测试上下文，使其断言真正的客户安全 fail-closed 原因。
2. 明确 75 个 HTTP 集成测试的启用条件，在 CI 提供 MySQL/Redis profile 并实际运行。
3. 为前端 `package.json` 增加标准 test 脚本，把 `vue-tsc`、lint、vitest、build 纳入同一 CI 门禁。
4. 建立只读数据库 schema/角色菜单/字典差异检查；先不自动迁移。

### 第二批：权限与数据库治理

1. 选择 Flyway 或受控手工 migration ledger，明确新装 baseline 与升级 migration 的边界。
2. 增加权限码契约检查：Controller、前端 `v-hasPermi`、菜单 SQL、业务角色 SQL 四方比对。
3. 为 `PROPERTY_WORKSPACE_PERMISSIONS` 增加测试，确保新增物业页面权限会触发正确项目初始化。
4. 为 BusinessContext/ReferenceType 建立穷举测试，禁止新增上下文后默认放行。
5. 增加 Service/Mapper 架构测试，约束项目/仓库资源必须经过统一 access service。

### 第三批：低风险代码卫生

1. 仅格式化收费与仓储的单行 Java 文件，不改语义；拆分为可 review 的标准结构。
2. 为 `RoomVo`、`BuildingVo` 明确 Lombok equals/hashCode 策略。
3. 统一 Maven/Surefire UTF-8，修复 Windows 控制台测试名乱码。
4. 对预期异常测试降低日志噪音或使用测试 appender 断言，保留真实异常信息。
5. 清点并处理明确属于示例模块的 TODO；扩展点 TODO 改成文档，不直接删除。

### 第四批：需要验证后再做

1. 替换 deprecated API，并先确认第三方升级兼容性。
2. 收敛 SuperAdmin 分散旁路，避免直接批量改权限逻辑。
3. 优化前端大 chunk，先使用 bundle analyzer 确认来源。
4. 评估 demo/AI/workflow 是否从物业 V1 部署 profile 排除，而不是删除源码。

## 2. 可安全清理候选

| 项目 | 风险 | 前置条件 |
|---|---|---|
| 前端补 `test`/`typecheck` 脚本 | 低 | 命令与本报告一致 |
| Java 单行源码纯格式化 | 低 | 独立提交，格式化前后测试一致 |
| Lombok 显式 `@EqualsAndHashCode` | 低 | 确认父类字段是否参与语义 |
| 测试/编译 UTF-8 配置 | 低 | Windows 与 CI 双环境验证 |
| 测试日志降噪 | 低 | 不隐藏非预期异常 |

## 3. 不建议直接清理

- `BusinessContext`、项目范围贡献器、WarehouseAccessService 与 SuperAdmin 分支。
- 客户加密、指纹、敏感访问审计与角色委派保护。
- 收款核销/冲销、库存变更、状态 CAS 与事务注解。
- 任何已存在 migration 或 baseline SQL。
- workflow/demo 中尚未确认部署用途的类。
- 前端当前项目 store 与仓储页面模式策略。

## 4. TASK-V1-002 建议验收标准

- 每个清理项独立提交、可回滚。
- 业务代码格式化与逻辑修改分离。
- 后端 43 模块编译通过，全量测试 0 failure/error，集成测试跳过数有明确清单。
- 前端 typecheck、lint、vitest、生产构建全部通过。
- 权限码四方契约检查通过。
- 不执行生产 migration；数据库治理先在一次性测试库验证。

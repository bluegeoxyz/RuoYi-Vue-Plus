# V1.0 开发数据库切换与回滚说明

## 当前连接

- 旧开发库：`zbm-data`，继续保留，仅作回滚候选，不受 Flyway 管理。
- 新开发库：`zbm_dev_v1`，开发 profile 默认连接该库并启用 Flyway。
- 数据库地址、用户和密码分别由 `ZBM_DB_URL`、`ZBM_DB_USERNAME`、`ZBM_DB_PASSWORD` 注入；密码无默认值，不写入仓库。
- V1 migration：`ruoyi-admin/src/main/resources/db/migration/V1__initial_schema.sql`。

## 启动

1. 设置 `ZBM_DB_PASSWORD`；如数据库不在默认地址，再设置 `ZBM_DB_URL` 和 `ZBM_DB_USERNAME`。
2. 设置应用已有的客户加密、HMAC、接口加密等安全密钥。
3. 使用 `dev` profile 启动。Flyway 会先执行 `validate`，再迁移未执行版本；`baselineOnMigrate=false`、`cleanDisabled=true`。
4. 新库管理员初始密码仅保存在本机被 Git 忽略的 `backups/TASK-V1-005-D/dev-credentials/admin-initial-password.txt`。需要轮换时运行 `script/sql/zbm/seed/Rotate-ZbmDevAdminPassword.ps1`；脚本会拒绝非 `zbm_dev_v1` 目标。

## 回滚

严重问题时仅恢复应用连接，不修改任何数据库：

1. 停止开发应用，保留 `zbm_dev_v1` 原状。
2. 临时把 `ZBM_DB_URL` 指向原 `zbm-data`，使用原开发库账号，并设置 `ZBM_FLYWAY_ENABLED=false`。
3. 启动后执行只读健康检查和登录检查。
4. 回滚不会删除新库、旧库或 Flyway 历史。再次切回新库前，应先定位问题并执行 `flyway validate`。

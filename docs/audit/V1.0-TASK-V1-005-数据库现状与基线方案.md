## 3. 索引和约束总览

- 61 张表均检测到主键。
- 业务表普遍具有项目/编码/单据号等唯一索引及查询普通索引。
- 收费、客户、仓储表合计存在多项 CHECK；系统核心表基本没有 CHECK。
- 物理 FOREIGN KEY 数量为 0。现有 baseline 明确选择由 Service 维护跨表一致性。
- 完整字段类型、默认值、索引定义的当前权威证据仍是 `SHOW CREATE TABLE`/`information_schema` 与 SQL 源文件；阶段 C 应生成机器可比较的结构清单，不能只比较表名。

## 6. 历史 migration 处理提案

项目尚未正式上线，但已有共享开发库曾手工执行部分 migration。建议：

1. 先冻结现有 37 个文件及 SHA-256，归档为 `legacy-development-migrations` 或在 README 标记“仅用于历史审计，不再用于新装”。
2. 不把这些文件改名冒充 Flyway V2 链，也不向现有库补写伪造的 `flyway_schema_history`。
3. 新环境以 `V1__initial_schema.sql` 为唯一 Flyway 起点；后续正式变更从 `V2__...sql` 开始。
4. 若阶段 D 决定重建开发库，先验证备份可恢复，再创建新空库跑 V1，最后通过受控 seed/数据迁移恢复确需保留的数据；不在原库清空历史表。
5. 正式上线后，所有已发布 Flyway migration 只增不改。

## 7. 新 V1 内容生成规则

### 纳入

- 经模块范围确认的系统、组织、用户、角色、菜单、字典、参数表。
- HR、物业项目/成员/授权、资源、客户/关系、收费/应收/收款/冲销、仓储主数据/库存/单据表。
- 当前代码要求的主键、唯一索引、普通索引、CHECK、字符集、时区/精度约束。
- 最小可启动的菜单、权限、字典、参数、内置角色。

### 排除或拆分

- `test_demo`、`test_tree`、`test_leave` 及其数据。
- 任意开发账号、项目、客户、收费和库存测试记录。
- 日志和消息历史。
- AI/Job/Workflow/Gen 对象，除非产品范围明确保留。
- 密码、加密/HMAC 密钥、OSS/SMS/Mail 密钥等敏感值。

## 8. 空库验证方案（阶段 C，未执行）

1. 创建专用空库和最小权限账号，库名必须与开发库不同。
2. 启用 Flyway，不设置 `baselineOnMigrate=true` 去迁就非空旧库。
3. 首次 `migrate` 应只产生 V1 和 `flyway_schema_history`。
4. `validate` 成功；第二次 `migrate` 输出无待执行迁移且不得重复建表/插数据。
5. 用 information_schema 对照表、列、默认值、主键、唯一/普通索引、CHECK。
6. 运行 Mapper smoke test、登录/授权、物业、客户、收费、仓储回归。
7. 导出结构差异报告和 Flyway history，作为阶段 C 验收证据。

本文件只提出方案，没有创建验证库或 V1 SQL。
